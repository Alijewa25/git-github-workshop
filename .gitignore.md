# .gitignore

The `.gitignore` file tells Git which files and directories should be ignored. Ignored files are not tracked and will not be included in commits or pushed to GitHub.

This helps keep repositories clean, secure, and organized.

---

# Why Use .gitignore?

Some files should never be stored in a Git repository.

Examples include:

* Temporary files
* Build files
* Dependency folders
* Environment variables
* Cache files
* Operating system files
* IDE configuration files

Ignoring these files reduces repository size and prevents sensitive information from being shared.

---

# What is a .gitignore File?

A `.gitignore` file contains patterns that Git uses to ignore specific files and folders.

Example:

```text
.gitignore
```

It is usually placed in the root directory of a repository.

---

# Basic Example

```text
node_modules/
.env
dist/
build/
```

Git will ignore these files and folders.

---

# Ignoring Individual Files

Ignore a single file.

```text
config.json
```

Git will ignore only that file.

---

# Ignoring Directories

Ignore an entire folder.

```text
logs/
```

Everything inside the folder will be ignored.

---

# Ignoring File Types

Ignore all files with a specific extension.

```text
*.log
*.tmp
*.cache
```

Examples:

```text
error.log
server.log
debug.log
```

All `.log` files will be ignored.

---

# Ignoring Environment Files

Environment files often contain passwords, API keys, and database credentials.

```text
.env
.env.local
.env.production
```

These files should never be uploaded to GitHub.


---

# Negation

Use `!` to stop ignoring a specific file.

Example:

```text
*.log
!important.log
```

All log files are ignored except:

```text
important.log
```

---

# Comments

Comments begin with `#`.

```text
# Ignore logs
*.log

# Ignore dependencies
node_modules/
```

---

# Checking Ignored Files

View ignored files.

```bash
git status --ignored
```

---

# Important Note

If a file has already been committed, adding it to `.gitignore` will **not** remove it from Git tracking.

Stop tracking the file first.

```bash
git rm --cached filename
```

Then commit the change.

---

# Best Practices

* Create a `.gitignore` file at the beginning of every project.
* Never upload API keys or passwords.
* Ignore dependency folders.
* Ignore build output.
* Ignore cache files.
* Ignore IDE configuration files.
* Keep the file updated as the project grows.

# Summary

The `.gitignore` file helps keep repositories clean by preventing unnecessary, temporary, generated, or sensitive files from being tracked by Git. Every project should include a properly configured `.gitignore` file to improve security, reduce clutter, and simplify collaboration.
